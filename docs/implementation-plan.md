## Phase 0: 基盤 + 認証（最優先。中身より先に鍵をかける）

### 0-1. プロジェクト初期化

- Vite + React + TypeScript でscaffold。`api/` ディレクトリ（Vercel Functions）を含むモノレポ構成（docs/api.md のディレクトリ構成に従う）
- ESLint + Prettier。テストは Vitest（ロジック部分のみで良い。UIスナップショットテストは不要）

**受け入れ条件**: `npm run dev` でローカル起動、`npm run build` が通る。

### 0-2. Vercel連携

- GitHub連携でpush時自動デプロイ。本番URLを確保

**受け入れ条件**: mainへのpushで本番URLに反映される。

### 0-3. Firebase Authentication（Googleログイン）

- Firebaseプロジェクト作成（ユーザーに作成/設定値の提供を依頼）
- フロント: `signInWithPopup`(Google) のログイン画面、未ログイン時の全ルートガード
- Functions: `api/_lib/auth.ts` — `verifyIdToken` + `ALLOWED_EMAILS` 照合（docs/api.md 共通仕様）
- 検証用の最小エンドポイントとして `/api/data` を先に作る（0-4と同時でも可）

**受け入れ条件**:

- 許可メールでログイン→データ取得成功
- 未ログイン/許可外メール → 401/403 が返り、UIは「アクセス権がありません」を表示
- `ANTHROPIC_API_KEY` 等のサーバ用環境変数がフロントバンドルに含まれない（`grep` で確認）

### 0-4. データ層（GitHub Contents APIプロキシ）

- `money-lens-data` Privateリポジトリ作成（ユーザーに依頼 or gh CLIで作成）
- `api/data.ts` の GET/PUT 実装（sha楽観ロック、fileパラメータの許可リスト検証）
- フロント側データアクセス層（`src/lib/dataClient.ts`）: 読み込みキャッシュ + 保存

**受け入れ条件**: 画面から settings.json 相当の値を読み書きでき、money-lens-data にコミットが積まれる。sha不一致時に409→再読込フローが動く。

## Phase 1: データ移行 + 可視化

### 1-1. Excel移行スクリプト

- `scripts/migrate_excel.py` を docs/data-migration.md の仕様通りに実装・実行
- `categories.json` / `budgets.json` / `settings.json` の初期値を配置

**受け入れ条件**: data-migration.md の検証チェックがすべてPASS。money-lens-data に初期データがpushされている。

### 1-2. ダッシュボード

- docs/ui.md の `/` を実装（サマリーカード、円グラフ、予算バー、12ヶ月推移棒グラフ、特別出費除外トグル）
- 集計ロジックは `src/lib/aggregate.ts` に純関数として分離し、Vitestでテスト（除外カテゴリ・特別出費除外・月境界）

**受け入れ条件**: 2025年の任意の月で、集計値がExcelから手計算した値と一致する（少なくとも1ヶ月分を照合）。excluded グループが集計に含まれない。

### 1-3. 明細一覧・編集

- `/transactions`: フィルタ、編集モーダル（カテゴリ変更・★フラグ・削除）、手動追加

**受け入れ条件**: 編集がmoney-lens-dataに保存され、リロード後も反映されている。

### 1-4. CSVインポート

- `/import`: ファイル/貼り付け両対応、プレビュー、重複検出、未知カテゴリの自動追加

**受け入れ条件**: 実データのCSV（既存明細と重複を含むもの）を貼り付けて、重複が正しく検出され、新規分のみ取り込まれる。

### 1-5. 給与・資産画面

- `/salary`: 手取り推移・控除内訳グラフ + 手動追加フォーム
- `/assets`: 残高推移グラフ + 月末残高入力

**受け入れ条件**: 2021-11以降の給与推移グラフが描画され、賞与が区別できる。残高推移に★月の注記が出る。

### 1-6. 設定画面

- `/settings`: カテゴリ管理・予算設定・口座管理

**受け入れ条件**: カテゴリのグループ変更がダッシュボードの集計に即反映される。

## Phase 2: AI分析

### 2-1. 分析API

- `api/analyze.ts` + `api/_lib/prompts.ts` + `api/_lib/ai/`（docs/api.md 準拠。AIプロバイダは `AI_PROVIDER` で抽象化、デフォルトはGemini、代替はAnthropic `claude-sonnet-5`。SSEストリーミング）
- フロントの集計サマリー生成（`src/lib/summarize.ts`、aggregate.ts を再利用）

**受け入れ条件**: 実データの月を分析させ、4段構成（事実→傾向→アクション→将来影響）の日本語出力がストリーミング表示される。出力中の金額が入力サマリーと矛盾しない。

### 2-2. チャットUI

- `/analysis` のチャット部分。会話履歴の保持、コンテキスト（当月サマリー）の注入

**受け入れ条件**: 「食費が多いけどどう減らす?」に対しデータに基づいた回答が返る。連続の質問で文脈が維持される。

## Phase 3: 将来シミュレーター

### 3-1. ライフイベント入力

- `/simulator` の入力フォーム（住宅ローン・出産/教育・収入変化・カスタム）→ `life-events.json`
- ローン計算（元利均等）と教育費標準値テーブルを `src/lib/simulate.ts` に純関数で実装 + テスト

**受け入れ条件**: 借入額/金利/期間から月額返済が正しく計算される（市販シミュレーターと照合）。

### 3-2. シナリオ試算 + スライダー

- 過去実績ベースライン（直近12ヶ月平均、特別出費除外）+ ライフイベントで3〜5年の月次キャッシュフロー/累積資産グラフ
- スライダー（貯金額・食費削減・繰上返済）で即時再計算、現状維持vs改善案の2系列比較

**受け入れ条件**: スライダー操作でグラフが遅延なく更新される。シナリオの前提が画面上に明示される。

### 3-3. AI講評

- シナリオ要約を `/api/chat` に渡して講評を得るボタン

**受け入れ条件**: シナリオの数値に基づいた講評が返る。

## 横断ルール（全フェーズ共通）

1. **セキュリティ**: architecture.md のセキュリティチェックリストを各フェーズ完了時に再確認する
2. **コミット**: 意味のある単位でコミット。データリポジトリ（money-lens-data）とアプリリポジトリを混同しない
3. **依存追加は最小限**: 設計書に書かれていないライブラリを足す場合は理由をコミットメッセージに書く
4. **金額計算はすべて整数（円）**: 浮動小数の誤差を避ける
5. **設計書の更新**: 実装中に設計とズレが生じたら、コードではなくまず docs/ を直してからコードを書く（docsが常に正）
